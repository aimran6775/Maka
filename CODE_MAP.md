## `sidecar/` — the one Node process

| Path | What it is |
| --- | --- |
| `sidecar/index.js` | Entry point. `boot({ env, port, host, log })` wires store, bus, layout state, optional `policy.json` / `leash.json` / `config.json` (`workspaceRoot`, `maxConcurrentRuns`, `reflectAt`) from `MAKA_HOME` (invalid files are reported and ignored), the workspace watcher, leash ledger, Gate queue, judge, agents (the Chief at the Peak), run manager, trails, Chief, scheduler, reflection cycle and server; prints where data lives, whether the workspace root is online, which providers are wired and the worker/judge routing. Workspace root: `MAKA_WORKSPACE`, else `config.json` `workspaceRoot`, else `~/Maka/workspace`. Exports `REPO_ROOT`. |
| `sidecar/workspace.js` | Workspace root watcher for a root on an external drive: polls `stat` + write access, emits `workspace.offline` (and stops the active run) / `workspace.online`, and the run manager refuses new runs while offline (`503 WORKSPACE_OFFLINE`). Nothing is ever written outside the root. |
| `sidecar/server.js` | HTTP routes (`/api/state`, `/api/events` SSE, `/api/run`, `/api/cancel`, `/api/layout` GET/PUT, `/api/layout/place`, `/api/layout/reclaim`, `/api/layout/reroll`, `/api/permission`, `/api/gate` GET, `/api/gate/:id` POST approve / revise / reject, `/api/leash` GET/PUT, `/api/agents` GET/POST, `/api/agents/:id` GET/PATCH/DELETE, `/api/agents/:id/pause` and `/resume` POST, `/api/work` GET/POST (the Superintendent delegates), `/api/work/:id`, `/api/work/:id/cancel`, `/api/mission` GET/POST, `/api/reflections`, `/api/reflections/:id`, `/api/reflect` POST, `/api/away` GET/POST, `/api/away/log`, `/api/mail/dns` GET, `/api/mail/dns/plan` POST, `/api/mail/dns/apply` POST (202, a Gate item), `/api/mail` GET, `/api/mail/addresses` GET/POST, `/api/mail/addresses/:address` DELETE, `/api/mail/messages` GET (filters), `/api/mail/messages/:id`, `/api/mail/threads` GET, `/api/mail/search`, `/api/mail/suppressions`, `/api/mail/sync` POST, `/api/mail/send` POST (the Superintendent, under the policy), `/api/mail/resend/webhook` POST (raw body, svix signature), `/api/runs`, `/api/runs/:id`), static `frontend/` (including `/vendor/` and `/assets/`) and `/shared/`. The state snapshot carries `leash`, `ledger` (today's totals), `gate` (pending + recent), `judge` (route, caps, today's spend), `agents` (the records), `activeRuns` / `queuedRuns` / `maxConcurrent`, `work` (in transit + recent) `mission` (mission, plan, the Chief, caps, judge spend today), `reflection` (latest, schedule, next run), `away` (flag, since, counters, last digest) and `mail` (domain, keys wired incl. the webhook secret, last DNS plan and apply, address and message counts, sync state). `/api/run` answers 202 with `queued`. `createLayoutState` applies placement rules (kind exists, tile in room, tile free) and emits validated `object.place` / `object.reclaim`. |
| `sidecar/runs.js` | Run manager: N runs at once (one per agent, `maxConcurrent` slots from `config.json` `maxConcurrentRuns`, default 4), each in its own workspace `<root>/<agentId>/`; a run for a busy agent or a full park is accepted, persisted as queued and announced with `agent.run.queued`, then started in arrival order when a slot frees (`active()`, `queued()`, `activeFor()`, `cancel(runId?)` for active or queued runs, `onRunEnd(fn)` hooks, `waitForIdle()` drains runs and writes). Picks the model through the router (explicit provider/model in the request wins, then a `step` kind such as `plan`, otherwise the worker tier; when Ollama is unreachable and the policy opts into `fallback.worker`, routine turns run on the hosted worker as tier `hosted_worker`, refused with `HOSTED_CAP` at its daily call cap) and records the tier and step on the run; one bus listener updates `spend.json` for every `cost.estimate` and counts hosted-worker calls in the ledger; picks the agent's own `policy.worker` over the router's worker tier when set; builds the gate for the agent's workspace (registry = phase 1 tools + crew tools, grants = fixtures + role, agents registry in the tool context) with the live leash policy, the leash ledger and the Gate queue, the judge's review hook for the run, and a system prompt carrying the agent's role, specialty, persona and venture; implements `ask` as a `permission.prompt` → `permission.response` round trip with a timeout (denial); expires the run's pending Gate items when it ends; records every event of the run and reconciled spend; persists through the store with debounced flushes. |
| `sidecar/agents.js` | Agent records and the hierarchy. `createAgents({ layoutState, leashState, bus })`: `list` / `get` (record + zone, reports, grants, resolved leash and overrides), `create`, `update` (name, zone with a free tile, parent, venture, specialty, persona, per-agent worker `policy`, budget, tile, leash overrides written to `leash.json`), `remove` (not with reports, not mid-run, never the last agent), `ensurePeak` (a room of kind `mountain_peak`), `ensureZone(kind, { venture })` (the first room of a kind, or of a kind and venture for trailheads, placed on the layout grid by `freeZoneRect`), `setPaused` (no new runs until resumed), `ensureChief` (the singleton `chief-ranger` at the Peak, created at boot). The record is the layout's agent entry (D45); every change emits `crew.agent`. `personaLines(agent)` builds the role / specialty / persona / venture lines of a run's system prompt. |
| `sidecar/trails.js` | Work items on trails. `createTrails({ bus, store, runs, agents, getLayout, workspaceRoot })`: `delegate({ toAgentId, brief, budgetUsd, deadline, evidence }, { by })` checks who may hand work to whom (the Chief to anyone, a Ranger to its own Juniors or other Rangers, the Superintendent to anyone; never a Junior, never to the Chief), persists the item, emits `work.handoff` and queues a run for the receiver with `briefFor(item)` as its prompt and the item's budget; the run manager's end hook closes the item (`work.done`: done or failed, the outbox files that appeared during the run as `deliverables`, the final text as `summary`, spend). `list`, `get`, `forAgent`, `inTransit`, `cancel`. Items persist in `work-items.json`; items left running at boot are marked failed. |
| `sidecar/chief.js` | The Chief Ranger's planning. `createChief({ bus, store, runs, agents, trails, ledger, router, getLayout, workspaceRoot })`: `mission({ text, budgetUsd, horizon })` persists the mission (`mission.json`) and runs the Chief on the router's `plan` step (judge tier, `claude-opus-5-5` by default, no judge review of the Chief) with `CHIEF_SYSTEM_PROMPT`; the Chief-only tools `plan.submit` (validated against `PLAN_SCHEMA`: ventures with roles, tasks, budgets, risks, what needs the owner; budget sums checked; stored in `plan.json` with history and written to the Chief's outbox as `plan-v<N>.md`; emits `plan.updated`) and `crew.hire` (a Ranger by specialty in its department camp, created on demand through `agents.ensureZone`); a `work.done` for an item the Chief delegated starts a follow-up run, bounded by `maxFollowUps` and by the judge daily cap (the mission pauses with the reason, `plan.updated { status }`). The Chief's cost events are counted as judge spend. `state()` feeds `/api/mission` and the Peak. |
| `sidecar/scheduler.js` | Cron-like scheduler: `nextRunAt(spec, afterMs)` is pure (`{ daily: 'HH:MM' }` local time or `{ everyMs }`); `createScheduler({ store, clock, tickMs })` adds jobs with a lock each, ticks every minute, runs what is due (reason `scheduled`, or `missed` when it was due while the sidecar was down), `trigger(id, reason)` runs one now, and persists last / next run per job in `scheduler.json`. Used by the reflection cycle; connector syncs reuse it. |
| `sidecar/reflect.js` | The reflection cycle. `createReflect({ bus, store, runs, agents, trails, chief, ledger, gateQueue, router, scheduler, ... })`: `gather()` collects per-venture actuals from persisted facts only (runs and reconciled spend since the mission, work items and deliverables, Gate decisions, judge spend; connectors stated as unknown); `reflect({ reason })` calls the router's `reflect` step model with `REFLECT_SYSTEM_PROMPT`, parses one JSON document (portfolio, per venture what worked / did not / plan still right / revisions / a morale note that must cite a number or is replaced by "no grounded note"; a briefing per department), stores it (`reflections/<id>.json`), writes it to the Chief's outbox and each briefing to `<root>/_stations/<zoneId>/notes/`, emits `cost.estimate { tier: 'judge' }` and `reflection.posted`, and hands the Chief a follow-up to revise the plan. At the judge cap, without a key, or on an unreadable answer the reflection is recorded and emitted as skipped with the reason. Budget watcher: per-agent spend from `cost.estimate` (seeded from persisted runs) emits `budget.threshold` once per 80 % / 100 % per venture, mission and judge day; 100 % on a venture or the mission triggers a reflection. Scheduled daily at `config.json` `reflectAt` (07:00). |
| `sidecar/away.js` | Away mode. `createAway({ bus, store, gateQueue, workspaceRoot, notify })`: `set(true)` persists the flag (`away.json`) and from then on appends every `gate.item`, `work.done`, `plan.updated`, `reflection.posted`, `budget.threshold` and `agent.run.error` as one line to the evidence log `<root>/_peak/away-log.ndjson` (append + fsync), counts actions, finished work and reconciled spend, and the Gate queue stamps `away: true` on action items; `set(false)` writes a digest (`<root>/_peak/digest-<id>.md` + `.json`: the window, counts by status, domain and Ranger, what still waits, work done, spend, notable events), emits `away.digest` and calls `notify` (mail to gate@ once mail exists). `state()` feeds `/api/away` and the Peak; `readLog()` the evidence lines. Survives a restart. |
| `sidecar/leash-ledger.js` | `createLeashLedger({ store, clock, earnApprovals })`: per local day and domain, executed actions and USD (`recordAction`, `spentToday`, `checkCap` against `dailyCapUsd` / `dailyCapActions`), judge spend per day (`recordJudge`, `judgeToday`, used by step 2), hosted worker calls and tokens per day (`recordHosted`, `hostedToday`, step 12b), and approval streaks per agent and domain (`recordDecision` reports when a streak reaches `earnApprovals` so a loosening proposal is raised). Persisted atomically in `leash-ledger.json`. Also `createLeashState({ initial, store })`: the live, validated leash policy, persisted to `leash.json` on every change. |
| `sidecar/gate-queue.js` | `createGateQueue({ bus, store, ledger, leashState })`: the Entrance Gate. `submit(item)` emits `gate.item { pending }` + `agent.waiting` and resolves with the Superintendent's decision; `resolve(itemId, { decision, notes })` emits the decided status, feeds the ledger streak and raises a kind `proposal` item when the streak earns one (approving a proposal writes the agent's new level through the leash state); `log(item)` records allowed / refused decisions the leash made alone; `expireRun(runId)` expires what a finished run left waiting. No timeout by default. Items persisted in `gate-items.json`; pending action items found at boot are marked expired. |
| `sidecar/router.js` | `createRouter(policy).route({ kind } | { tier })` → `{ tier, provider, model }`, `caps()`, `fallbackFor(tier)`. Policy is validated data (`POLICY_SCHEMA`, `defaultPolicy()`: worker = ollama; judge = anthropic / `claude-sonnet-5-5`; `hosted_worker` = huggingface / `Qwen/Qwen2.5-72B-Instruct`, used only when a step, an agent policy or the opt-in `fallback.worker` names it; `turn` → worker, `plan` / `review` / `ambiguity` / `gate_action` / `reflect` → judge; `stepModels` per-step overrides, by default `plan` and `reflect` on `claude-opus-5-5`; caps `judgeCallsPerRun` 20, `judgeCallsPerDay` 500, `judgeUsdPerDay` 10, `hostedWorkerCallsPerDay` 2000). Loaded from `$MAKA_HOME/policy.json` when present. |
| `sidecar/judge.js` | The judge step. `createJudge({ router, makeProvider, ledger, bus })` → `forRun({ runId, agentId, gate, brief })` returns the loop's `review` hook: it calls the judge model before any tool call in a non-research domain at act_capped / act_free, or at draft when the tool asks (`tool.judgeAtDraft(input)`, mail to a new external recipient) (`needsActionReview`), and before the run ends (`final`), with a system prompt that demands one JSON verdict (`parseVerdict`). Each call emits `cost.estimate { tier: 'judge' }` and `judge.verdict`, is counted in the ledger's judge totals, and returns its cost to the loop. At the daily USD / call caps, without a key, or when the call fails it emits `judge.verdict { skipped, reason }` and escalates the action to the Gate as Draft for review. `status()` feeds `/api/state.judge`. |
| `sidecar/bus.js` | Event bus: validates, assigns `seq`, keeps a 2000-event buffer, fans out to listeners and SSE clients, replays after `Last-Event-ID`. |
| `sidecar/store.js` | `writeJsonAtomic` (temp → fsync → rename → fsync dir) and the store: `layout.json`, `spend.json`, `leash.json`, `leash-ledger.json`, `gate-items.json`, `work-items.json`, `mission.json`, `plan.json`, `scheduler.json`, `away.json`, `mail-addresses.json`, `reflections/<id>.json`, `runs/<runId>.json`. |
| `sidecar/loop.js` | The agentic loop, `runLoop(options)`. Messages-array while-loop; guards (cancelled / max turns / budget) before every paid call; content blocks accumulated by index; one `agent.tool_result` per `agent.tool_call`; provider failure emits `agent.run.error` and no `agent.run.end`. `tier` is stamped on each `cost.estimate`. `review` is the pre-Gate hook point for the phase 2 judge: revise/reject answers the turn's tool calls with the notes instead of running them. Tools receive the turn's text (`ctx.turnText`) so Gate items carry what the Ranger said as evidence, and the review verdict (`ctx.review`, with `escalate`). A final review (no tool calls) that says revise / reject becomes a new user turn, at most `maxReviewRetries` (2) times; a verdict's `usd` counts against the run budget. Pure given injected `provider`, `tools`, `emit`, `clock`, `signal`, `ids`. Also exports `costOf(usage, price)`. |

A tool may declare `amountUsd(input)` and `summarize(input)`.
