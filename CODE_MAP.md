## `shared/` — loaded by both the sidecar and the frontend as ES modules

| Path | What it is |
| --- | --- |
| `shared/schema.js` | Tiny JSON-schema-like validator: `validate`, `assertValid`, `deepFreeze`. Supports type, properties/required/additionalProperties, items, enum, const, min/max for strings, numbers and arrays, anyOf. Nothing else. |
| `shared/world.js` | World data: `OBJECT_KINDS` (fixtures: trailhead_sign → `web.fetch`; supply_cache → `fs.read` + `fs.write`), `AGENT_ROLES` (superintendent, chief_ranger, ranger, junior_ranger), `PARENT_ROLES` (who may report to whom: a Junior's parent is a Ranger, one hop), `ROLE_GRANTS` / `roleGrants` (tools granted by role: `crew.spawn_junior` for chief and ranger), `SPECIALTIES` (scout, storefront, ads, marketing, support, books: label, home zone kind, default persona), `ZONE_KINDS`, `ZONE_LABELS`, `freeZoneRect` (ranger_station, entrance_gate, mountain_peak, visitor_center, trailhead and the six departments), `LAYOUT_SCHEMA` (rooms with optional `kind`, objects, agents with optional `role`, `parentAgentId`, `venture`, `specialty`, `persona`, `policy.worker`, `budgetUsd`, `createdBy`, `createdAt`; park `seed`), `defaultLayout()` (one zone "Ranger Station", one Ranger), `grantsFor` (fixtures), `allGrantsFor` (fixtures + role), `childrenOf`, `freeTile`. Zones are `rooms` and fixtures are `objects` on the wire; those names are frozen. Fixtures for phase 2 connectors (radio tower, park store, notice board, fee booth, ledger desk) are not listed because their tools do not exist. |
| `shared/leash.js` | Leash model as data: `LEASH_LEVELS` (observe → draft → act_capped → act_free), the nine `DOMAINS`, `TOOL_DOMAINS` (`fs.read` and `web.fetch` → research; `fs.write` → none, it is workspace-only and confirmed per call), `LEASH_SCHEMA` (park `domains`, optional `zones[roomId]` and `agents[agentId]` overrides, per-entry `dailyCapUsd` / `dailyCapActions`, `earn.approvals`), `defaultLeash()` (draft everywhere, research act_free, money_out capped at $0), `resolveLeash(leash, { agentId, roomId }, domain)` (agent → zone → park → draft, reports the `scope`), `resolveAllLeash`, `withAgentLeash`, `nextLooser`, `leashFor`. Enforced by `sidecar/capability/gate.js` since phase 2 step 1. |
| `shared/events.js` | The frozen, additive-only event contract. `EVENT_TYPES`, `PAYLOAD_SCHEMAS`, `ENVELOPE_SCHEMA`, `validateEvent`, `assertEvent`, `makeEvent`. Twenty-two events: `agent.run.start`, `agent.token`, `agent.tool_call`, `agent.tool_result`, `agent.run.end`, `agent.run.error`, `cost.estimate` (optional `tier`), `permission.prompt` (optional `leash`), `permission.response`, `object.place`, `object.reclaim`, `work.handoff` (phase 2 step 4 emits it), `layout.seed`, `workspace.offline`, `workspace.online`, and from phase 2 step 1 `gate.item` (one per status change of an Entrance Gate item: `GATE_ITEM_STATUSES` pending / approved / revised / rejected / allowed / refused / expired, `GATE_ITEM_KINDS` action / proposal) and `agent.waiting` (a run parked on a Gate item); from step 2 `judge.verdict` (approve / revise / reject / skipped, scope action or final, model and cost); from step 3 `crew.agent` (an agent record created / updated / removed, with the record); from step 4 `work.done` (a work item finished: done / failed, deliverables, summary, spend) and `agent.run.queued` (a run waiting for its agent or a slot); from step 5 `plan.updated` (a plan version submitted, or the mission's status: planning / active / paused / done). |

## `sidecar/` — the one Node process

| Path | What it is |
| --- | --- |
| `sidecar/index.js` | Entry point. `boot({ env, port, host, log })` wires store, bus, layout state, optional `policy.json` / `leash.json` / `config.json` from `MAKA_HOME` (invalid files are reported and ignored), the workspace watcher, run manager and server; prints where data lives, whether the workspace root is online, which providers are wired and the worker/judge routing. Workspace root: `MAKA_WORKSPACE`, else `config.json` `workspaceRoot`, else `~/Maka/workspace`. Exports `REPO_ROOT`. |
| `sidecar/workspace.js` | Workspace root watcher for a root on an external drive: polls `stat` + write access, emits `workspace.offline` (and stops the active run) / `workspace.online`, and the run manager refuses new runs while offline (`503 WORKSPACE_OFFLINE`). Nothing is ever written outside the root. |
| `sidecar/server.js` | HTTP routes (`/api/state`, `/api/events` SSE, `/api/run`, `/api/cancel`, `/api/layout` GET/PUT, `/api/layout/place`, `/api/layout/reclaim`, `/api/layout/reroll`, `/api/permission`, `/api/gate` GET, `/api/gate/:id` POST approve / revise / reject, `/api/leash` GET/PUT, `/api/agents` GET/POST, `/api/agents/:id` GET/PATCH/DELETE, `/api/work` GET/POST (the Superintendent delegates), `/api/work/:id`, `/api/work/:id/cancel`, `/api/mission` GET/POST, `/api/runs`, `/api/runs/:id`), static `frontend/` (including `/vendor/` and `/assets/`) and `/shared/`. The state snapshot carries `leash`, `ledger` (today's totals), `gate` (pending + recent), `judge` (route, caps, today's spend), `agents` (the records), `activeRuns` / `queuedRuns` / `maxConcurrent`, `work` (in transit + recent) and `mission` (mission, plan, the Chief, caps, judge spend today). `/api/run` answers 202 with `queued`. `createLayoutState` applies placement rules (kind exists, tile in room, tile free) and emits validated `object.place` / `object.reclaim`. |
| `sidecar/runs.js` | Run manager: N runs at once (one per agent, `maxConcurrent` slots from `config.json` `maxConcurrentRuns`, default 4), each in its own workspace `<root>/<agentId>/`; a run for a busy agent or a full park is accepted, persisted as queued and announced with `agent.run.queued`, then started in arrival order when a slot frees (`active()`, `queued()`, `activeFor()`, `cancel(runId?)` for active or queued runs, `onRunEnd(fn)` hooks, `waitForIdle()` drains runs and writes). Picks the model through the router (explicit provider/model in the request wins, then a `step` kind such as `plan`, otherwise the worker tier) and records the tier and step on the run; one bus listener updates `spend.json` for every `cost.estimate`; picks the agent's own `policy.worker` over the router's worker tier when set; builds the gate for the agent's workspace (registry = phase 1 tools + crew tools, grants = fixtures + role, agents registry in the tool context) with the live leash policy, the leash ledger and the Gate queue, the judge's review hook for the run, and a system prompt carrying the agent's role, specialty, persona and venture; implements `ask` as a `permission.prompt` → `permission.response` round trip with a timeout (denial); expires the run's pending Gate items when it ends; records every event of the run and reconciled spend; persists through the store with debounced flushes. |
| `sidecar/agents.js` | Agent records and the hierarchy. `createAgents({ layoutState, leashState, bus })`: `list` / `get` (record + zone, reports, grants, resolved leash and overrides), `create`, `update` (name, zone with a free tile, parent, venture, specialty, persona, per-agent worker `policy`, budget, tile, leash overrides written to `leash.json`), `remove` (not with reports, not mid-run, never the last agent), `ensurePeak` (a room of kind `mountain_peak`), `ensureZone(kind)` (the first room of a kind, placed on the layout grid by `freeZoneRect`), `ensureChief` (the singleton `chief-ranger` at the Peak, created at boot). The record is the layout's agent entry (D45); every change emits `crew.agent`. `personaLines(agent)` builds the role / specialty / persona / venture lines of a run's system prompt. |
| `sidecar/trails.js` | Work items on trails. `createTrails({ bus, store, runs, agents, getLayout, workspaceRoot })`: `delegate({ toAgentId, brief, budgetUsd, deadline, evidence }, { by })` checks who may hand work to whom (the Chief to anyone, a Ranger to its own Juniors or other Rangers, the Superintendent to anyone; never a Junior, never to the Chief), persists the item, emits `work.handoff` and queues a run for the receiver with `briefFor(item)` as its prompt and the item's budget; the run manager's end hook closes the item (`work.done`: done or failed, the outbox files that appeared during the run as `deliverables`, the final text as `summary`, spend). `list`, `get`, `forAgent`, `inTransit`, `cancel`. Items persist in `work-items.json`; items left running at boot are marked failed. |
| `sidecar/chief.js` | The Chief Ranger's planning. `createChief({ bus, store, runs, agents, trails, ledger, router, getLayout, workspaceRoot })`: `mission({ text, budgetUsd, horizon })` persists the mission (`mission.json`) and runs the Chief on the router's `plan` step (judge tier, `claude-opus-5-5` by default, no judge review of the Chief) with `CHIEF_SYSTEM_PROMPT`; the Chief-only tools `plan.submit` (validated against `PLAN_SCHEMA`: ventures with roles, tasks, budgets, risks, what needs the owner; budget sums checked; stored in `plan.json` with history and written to the Chief's outbox as `plan-v<N>.md`; emits `plan.updated`) and `crew.hire` (a Ranger by specialty in its department camp, created on demand through `agents.ensureZone`); a `work.done` for an item the Chief delegated starts a follow-up run, bounded by `maxFollowUps` and by the judge daily cap (the mission pauses with the reason, `plan.updated { status }`). The Chief's cost events are counted as judge spend. `state()` feeds `/api/mission` and the Peak. |
| `sidecar/leash-ledger.js` | `createLeashLedger({ store, clock, earnApprovals })`: per local day and domain, executed actions and USD (`recordAction`, `spentToday`, `checkCap` against `dailyCapUsd` / `dailyCapActions`), judge spend per day (`recordJudge`, `judgeToday`, used by step 2), and approval streaks per agent and domain (`recordDecision` reports when a streak reaches `earnApprovals` so a loosening proposal is raised). Persisted atomically in `leash-ledger.json`. Also `createLeashState({ initial, store })`: the live, validated leash policy, persisted to `leash.json` on every change. |
| `sidecar/gate-queue.js` | `createGateQueue({ bus, store, ledger, leashState })`: the Entrance Gate. `submit(item)` emits `gate.item { pending }` + `agent.waiting` and resolves with the Superintendent's decision; `resolve(itemId, { decision, notes })` emits the decided status, feeds the ledger streak and raises a kind `proposal` item when the streak earns one (approving a proposal writes the agent's new level through the leash state); `log(item)` records allowed / refused decisions the leash made alone; `expireRun(runId)` expires what a finished run left waiting. No timeout by default. Items persisted in `gate-items.json`; pending action items found at boot are marked expired. |
| `sidecar/router.js` | `createRouter(policy).route({ kind })` → `{ tier, provider, model }`, `caps()`. Policy is validated data (`POLICY_SCHEMA`, `defaultPolicy()`: worker = ollama; judge = anthropic / `claude-sonnet-5-5`; `turn` → worker, `plan` / `review` / `ambiguity` / `gate_action` / `reflect` → judge; `stepModels` per-step overrides, by default `plan` and `reflect` on `claude-opus-5-5`; caps `judgeCallsPerRun` 20, `judgeCallsPerDay` 500, `judgeUsdPerDay` 10). Loaded from `$MAKA_HOME/policy.json` when present. |
| `sidecar/judge.js` | The judge step. `createJudge({ router, makeProvider, ledger, bus })` → `forRun({ runId, agentId, gate, brief })` returns the loop's `review` hook: it calls the judge model before any tool call in a non-research domain at act_capped / act_free (`needsActionReview`) and before the run ends (`final`), with a system prompt that demands one JSON verdict (`parseVerdict`). Each call emits `cost.estimate { tier: 'judge' }` and `judge.verdict`, is counted in the ledger's judge totals, and returns its cost to the loop. At the daily USD / call caps, without a key, or when the call fails it emits `judge.verdict { skipped, reason }` and escalates the action to the Gate as Draft for review. `status()` feeds `/api/state.judge`. |
| `sidecar/bus.js` | Event bus: validates, assigns `seq`, keeps a 2000-event buffer, fans out to listeners and SSE clients, replays after `Last-Event-ID`. |
| `sidecar/store.js` | `writeJsonAtomic` (temp → fsync → rename → fsync dir) and the store: `layout.json`, `spend.json`, `leash.json`, `leash-ledger.json`, `gate-items.json`, `work-items.json`, `mission.json`, `plan.json`, `runs/<runId>.json`. |
| `sidecar/loop.js` | The agentic loop, `runLoop(options)`. Messages-array while-loop; guards (cancelled / max turns / budget) before every paid call; content blocks accumulated by index; one `agent.tool_result` per `agent.tool_call`; provider failure emits `agent.run.error` and no `agent.run.end`. `tier` is stamped on each `cost.estimate`. `review` is the pre-Gate hook point for the phase 2 judge: revise/reject answers the turn's tool calls with the notes instead of running them. Tools receive the turn's text (`ctx.turnText`) so Gate items carry what the Ranger said as evidence, and the review verdict (`ctx.review`, with `escalate`). A final review (no tool calls) that says revise / reject becomes a new user turn, at most `maxReviewRetries` (2) times; a verdict's `usd` counts against the run budget. Pure given injected `provider`, `tools`, `emit`, `clock`, `signal`, `ids`. Also exports `costOf(usage, price)`. |

| `sidecar/providers/provider.js` | The provider contract (normalized stream chunks) and registry for `anthropic`, `openrouter`, `ollama`: `createProvider(name, opts)` resolves a key (or, for ollama, a model) and a price; `providerStatus()` reports keyed providers as configured or not and ollama as reachable or not with its installed models, never revealing a key. |
| `sidecar/providers/anthropic.js` | Anthropic Messages API over raw `fetch`, streaming, tool use. Keeps `thinking` blocks verbatim and replays them. Default model `claude-opus-5-5`. |
| `sidecar/providers/openai-compat.js` | Shared adapter for OpenAI-compatible chat-completions endpoints: message/tool translation both ways, streamed tool calls accumulated by index, `cost(usage)` hook. |
| `sidecar/providers/openrouter.js` | OpenRouter on top of `openai-compat.js`; forwards OpenRouter's reported `usage.cost` as reconciled spend. |
| `sidecar/providers/ollama.js` | Ollama (local worker models) on top of `openai-compat.js` at `OLLAMA_HOST` (default `http://127.0.0.1:11434`). No key. Every turn costs a reconciled $0. `listModels()` / `probe()` ask the server what is installed; the registry picks `OLLAMA_MODEL` or the first installed model and fails with `NO_MODEL` / `OLLAMA_UNREACHABLE` otherwise. |
| `sidecar/providers/sse.js` | `text/event-stream` parser and HTTP error helper shared by both adapters. |
| `sidecar/providers/keys.js` | Key resolution: env var first, then `.maka/keystore.json` which must be mode 0600 (refused otherwise). `setKey` writes it 0600. Keys never leave this module except into a request header. |
| `sidecar/providers/pricing.js` | List prices per million tokens for known Anthropic models. Unknown model → `null` → unreconciled cost. |

| `sidecar/capability/tools.js` | The three phase 1 tools. `fs.read` and `fs.write` are sandboxed to the agent workspace via real-path checks (no `..`, no symlink escapes), with size caps and visible truncation notes. `web.fetch` is GET-only http(s) with a timeout, size cap and HTML-to-text. `fs.write` is marked `confirm: true`. |
| `sidecar/capability/crew.js` | Role-granted tools (chief and ranger; the Chief also gets `plan.submit` and `crew.hire` from `sidecar/chief.js`). `crew.spawn_junior` creates a Junior Ranger under the caller in its zone through the injected agents registry (`toolContext.agents`); `delegate` hands a work item to another agent through `toolContext.trails` and returns at once with the item id; `work.check` lists the caller's sent and received items (status, summary, deliverables, spend) or reads one. No leash domain. |
| `sidecar/capability/gate.js` | `createToolGate(...)` turns the current layout into the `tools` object the loop uses: `definitions()` lists only granted tools (fixtures, or an injected `grants()`; the run manager passes `allGrantsFor` = fixtures + role); `execute()` re-checks the grant at call time, validates input, then enforces the leash for tools with a domain (`tool.domain` or `TOOL_DOMAINS`): observe → typed refusal `LEASH_OBSERVE`; draft → a pending Gate item via `submit`, approve runs it, revise / reject answer the call (`GATE_REVISE` / `GATE_REJECT`); act_capped → runs while the ledger's daily caps hold, else a Gate item; act_free → runs, counted in the ledger and (outside research) logged at the Gate as allowed. A tool may declare `amountUsd(input)` and `summarize(input)`. Tools without a domain keep the per-call `ask` confirmation. `leashFor(tool)` reports the resolved entry. |

**Verified** in headless Chromium (SwiftShader WebGL2) against a test sidecar with a
scripted provider: renderer boots, kit models and the FBX Ranger with clips load, a run
from COMMS raises the Gate card with the leash level, the Ranger badge follows the run,
allow completes the run, camera modes switch, re-roll changes the seed, no page errors. The
driver script lives outside the repo; it is a manual check, not part of `test:fast`.

**Not verified / not implemented:** the 60 fps on Apple Silicon target (SwiftShader here
renders at a few fps, which says nothing about a GPU); distance LOD for foliage (instancing
and frustum culling only); the WebGPU renderer path (WebGL2 only, see DECISIONS D27);
walking on handoffs is implemented but exercised only by the reducer test, since phase 1
emits no `work.handoff`.
